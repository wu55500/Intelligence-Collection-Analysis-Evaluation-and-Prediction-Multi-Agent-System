# Suggested addition to the project's existing agent instructions

For new projects, use the `project-agent-engineering-governance` skill. Work backward from the target user/problem and target role's competencies; inspect reference repositories without copying blindly; map requirements to modules, interfaces, technology choices, tests and evidence; and complete the resource/environment feasibility gate before committing to architecture. For existing projects, inspect the real repository and preserve user work before editing. Establish scope, non-goals, risk level, acceptance criteria and a rollback/verification plan. Make small reversible changes and review the actual diff. Treat AI output as untrusted draft work that must be explained, tested and maintained. Record only AI/model reviews that actually happened. UI importance depends on the target role. Report only checks that ran, with commands/results/evidence; hard security, data-loss, permission, approval and reproducibility gates override any score. Finish with `COMPLETE`, `PARTIAL` or `BLOCKED`, residual risks, and resume claims supported by artifacts.
