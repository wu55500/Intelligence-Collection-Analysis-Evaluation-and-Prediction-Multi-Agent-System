# 专业领域能力映射表

## 核心原则

本项目的专业能力不是简单的技术栈堆砌，而是将专业知识转化为可运行、可验证、可追溯、可恢复、可持续改进的业务能力。

## 专业知识如何转化为系统能力

### 示例：行业需求变化分析

假设用户想分析某行业未来需求变化，各专业的协同流程：

1. **数据工程（M1）**
   - 采集历史指标和相关公开资料
   - 多源检索、反向检索、一手源直读
   - 输出：原始证据列表

2. **数据治理（M2）**
   - 处理缺失值、重复来源、统计口径差异
   - 清洗去重、异常值净化、分层标注S/B/C
   - 输出：结构化数据集

3. **统计分析（M3/M5）**
   - 检查趋势、异常和变量之间的关系
   - EDA探索、双系数（Pearson+Spearman）、因果审查门
   - 输出：可复算的统计结论

4. **Agent推理（研究/分析执行单元）**
   - 形成待验证的解释
   - 选择适用的分析工具
   - 输出：假设列表、工具调用结果

5. **预测模型（M8）**
   - 给出概率性结果和不确定性范围
   - 预测登记、证伪锚点、到期日
   - 输出：预测记录（不可覆盖）

6. **独立验证（确定性治理层）**
   - 检查数据泄漏、历史回测、基线表现
   - 承诺等级评估（A/B/C/D/BLOCKED）
   - 输出：验证报告、承诺等级

7. **运筹优化（M9/M17，按需）**
   - 比较不同资源配置方案
   - 约束满足、目标函数优化
   - 输出：方案对比、敏感性分析

8. **报表与交互（前端）**
   - 展示结果、证据、假设和适用条件
   - 业务指标报表、证据关系图、工作流视图
   - 输出：交互式报告

9. **预测结算（M8）**
   - 保存预测，在未来实际结果出现后结算
   - 计算Brier Score、校准度
   - 输出：预测表现评估

## 关键转化原则

1. **可运行**：每个专业知识都有对应的代码实现
2. **可验证**：每个结论都可追溯到证据和方法
3. **可追溯**：每个数字都可复算，每个判断都有依据
4. **可恢复**：任务中断可从断点恢复，不丢失状态
5. **可持续改进**：通过预测结算和Brier Score持续校准

## 手机端开发的特殊考虑

- **手机作为入口**：开发、操作、展示
- **云端承载重计算**：LLM调用、统计分析、长时间任务
- **本地轻量存储**：SQLite存储任务状态、断点恢复
- **API客户端**：调用云端服务，不本地运行重量级进程
- **不能假设**：手机上Python进程可长期驻留
